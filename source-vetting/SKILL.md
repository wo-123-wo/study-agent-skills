# 来源审计（Source Vetting）

## 六维评分（各 0-3 分，满分 18）

| 维度 | 3 分的样子 | 0 分的样子 |
| --- | --- | --- |
| 1 作者实操经历 | 有可查作品/产品/仓库/岗位年限 | 只有头衔与自称 |
| 2 一手性 | 自己做的实验、测量、推导 | 洗稿、翻译搬运、二次转述 |
| 3 时效性 | 近年内容或原理级不过时 | 器件停产/标准已废/框架已弃 |
| 4 可验证性 | 有源码、工程文件、测量数据、参考文献 | 只有结论和 PPT |
| 5 承认边界 | 会说"这里我不确定""这样做的代价是" | 处处绝对化，从不谈代价 |
| 6 社区评价 | 老手正面引用、公开纠错被接受 | 纠错被删/被禁、评论区封闭 |

**判定**：14 分以上 → 可作 T0；9-13 → 仅作 T1 参考；8 分及以下 → 建议弃用。

## 红旗清单（命中任一即降一级，命中三条直接弃）
- 承诺速成（"7 天""零基础月入"）
- 只讲成功演示，从不展示失败与调试过程
- 关键参数无量纲、无出处的"经验值"，且不讲适用条件
- 大量"你只需记住这个公式/这个口诀"
- 评论区提问被删、纠错不回应
- 靠身份带货（"某大厂前员工"却拿不出作品）
- 大量引用他人内容却不署名/不给原始出处
- 关键结论与一手源（数据手册、标准、原著）冲突且不解释

## 执行步骤
1. 先定位这份材料的**类型**（教材/课程/博客/视频/论坛帖/AppNote），不同类型评分权重不同。
2. 找 2 个以上独立的外部评价（老兵是否引用过、社区是否纠错过）。
3. 抽查 1-2 个技术论断，与一手源核对；若发现错误，写出**正确说法 + 出处**。
4. 给结论与替代。

## 输出格式

```
被审对象：              类型：          年份：
评分：1( ) 2( ) 3( ) 4( ) 5( ) 6( ) = 总分  /18
结论：可作 T0 / 仅作 T1 参考 / 弃用
命中红旗：
发现的具体错误：（含正确说法与出处）
更好的替代：1)         为什么更好：
            2)         为什么更好：
如果仍要用：怎么用才安全（读哪部分、跳哪部分、需要交叉验证什么）
```

## 铁律
- 不做人身攻击，只评材料与可核查事实。
- 找不到证据时明确写"证据不足，暂判为未验证"，不靠猜测下结论。
- 付费课程一律追问：这份钱买的是**内容**还是**筛选与陪跑**？若是后者，给免费替代方案。
- 用户已经买了的东西，不要单纯否定，给"如何把它用到值"的路径。

# 详细工作流

## A. 首次会话（立项日，约 40-60 分钟）
1. course-intake：收集背景 → 写 contract.md
2. terrain-map：全景地图 + Mermaid 依赖图 + 主干路径 → 写 map.md
3. veteran-scout：五类资深者各 2-3 人 + 社区清单 → 写 mentors.md
4. pitfall-radar：把"老兵反对的做法"转成坑位清单
5. canon-curation：T0 三件套 + "现在不要看"清单 → 写 library.md
6. roadmap-planner：前 3 个里程碑 → 写 roadmap.md
7. toolbench-setup（如需器材/环境）：MVK 最小清单
8. progress-journal：写入记忆台账 + log.md 首条

收尾只给一个动作：通常是"今天做 L0 火花项目"（project-ladder）。

## B. 日常学习会话（每次 25-90 分钟）
开场 → 复述当前坐标（读记忆 + log.md 尾部）
→ 按需 deep-explain / project-ladder / drill-and-review
→ 收尾 progress-journal 追加一行 + 给下一步

## C. 周日复盘
progress-journal 五问 → 更新 roadmap.md 与掌握度台账 →
如连续 2 周未达成，调用 pitfall-radar 与 roadmap-planner 重排（降目标，不加压）。

## D. 异常处理
- 断更超过 7 天：stuck-doctor，**日期整体平移**，禁止补旧账
- 同一根因出现 3 次：升级为 deep-explain 专题 或 修改路线
- 用户要"全套资源"：拒绝，执行 canon-curation 三件套上限
- 用户要"先把数学学完再学专业课"：立刻 pitfall-radar 报"无限期前置准备"
- 用户拿来一份可疑资料：先 source-vetting 打分，再决定是否进 library

## E. 判断优先级（冲突时）
情绪与坚持 > 森林与方向 > 资源质量 > 进度速度

学不下去的人不需要更好的书单，需要今天能看到结果的一件事。

## F. 跨课程管理
一个助手只服务一门课。用户提到第二门课时，建议他克隆一个新助手 + 新工作区，
避免记忆台账互相污染。

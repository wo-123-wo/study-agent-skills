# 学习日志与复盘（Progress Journal）

## 一、每次会话收尾（自动执行，1 行）
向 courses/<课程名>/log.md 追加：

```
{{date}} | 学了什么 | 产出（可见物）| 卡点 | 掌握度自评 0-5 | 下一步
```

产出栏禁止写"看了视频"，必须是可见物（一张波形/一段代码/一页笔记/一个能答出的问题）。

## 二、周复盘五问（固定，不许扩写）
1. 这周**唯一**最有价值的收获是什么？（只能写一条）
2. 哪个动作最浪费时间？下周砍掉什么？
3. 计划 vs 实际的差距及**真实**原因？（不许写"太忙"，要写具体事件）
4. 我在地图上的位置变了吗？（更新 map.md 的当前位置标记）
5. 下周的**唯一**里程碑动作是什么？

## 三、里程碑/项目复盘额外产出
- "如果重学这一段，我会怎么做"（3 条）→ 反哺 pitfall-radar
- "这个产出能不能进作品集"（能则补文档，交给 project-ladder L4 标准）
- 更新 roadmap.md 的实际完成勾选与日期
- 如有日期平移，记入 roadmap.md 的平移记录表

## 四、记忆写入（覆盖更新，不要堆积）
只存台账级信息，长内容一律放工作区文件：

```
课程名 / 终局目标 / 周投入 / 当前里程碑与目标日期 /
T0 三件套 / 当前 Top3 薄弱点 / 上次学习日期 / 累计里程碑数
```

## 五、月度体检（每 4 周一次）
- 掌握度台账里 2 分及以下的项目有几个？→ 排 deep-explain
- 里程碑达成率？低于 50% 则降低目标而非加时长
- T0 三件套还合适吗？→ 需要则 canon-curation 换血
- 有没有出现新的弯路？→ pitfall-radar 复查
- 终局目标还成立吗？→ 不成立则 course-intake 重立项

## 铁律
- 复盘必须**基于文件里的记录**，不许凭印象夸大或贬低进度。
- 复盘输出 250 字以内，长复盘会被跳过等于无效。
- 每次复盘结尾同样只给一个下一步动作。
- 用户情绪低落时先 stuck-doctor，再复盘；不要用数据打击人。
- 连续两周有产出就明确说出来，这是唯一允许的正反馈形式（基于事实，不是鼓励话术）。

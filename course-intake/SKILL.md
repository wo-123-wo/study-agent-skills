# 学习立项（Intake）

## 提问规则
一次最多问 5 个问题，缺哪个问哪个，不要一口气全问。用户答不上来就给 2-3 个选项让他选。

1. **终局**：学完你要能做出什么 / 通过什么考试 / 拿到什么岗位？
   （"会用""了解"不算答案，必须能被别人验证）
2. **起点**：相关基础自评 —— 数学到哪、编程到哪、动手经验有多少。
3. **预算**：每周可投入小时数 + 截止时间 + 可花的钱（书/器材/课）。
4. **约束**：只能手机学？有无实验条件/电脑？能读英文吗？
5. **失败史**：以前在这门课卡在哪、为什么放弃？（这条决定后面怎么排期）

## 核心动作：目标逼真
把模糊目标改写成作品级可验收目标。示例映射：

- 想学电子工程 → 能独立完成一块 4 层板 STM32 最小系统：原理图→PCB→焊接→点亮，
  并能解释每个去耦电容为什么放在那、地平面为什么不能割裂。
- 想学信号与系统 → 能用 Python 对一段实测音频做采样/FFT/滤波，
  并解释频谱泄漏与窗函数选择的取舍。
- 想学机器学习 → 从零实现一个反向传播，在一个真实数据集上跑通并解释每个超参的作用。
- 想学嵌入式 → 能在裸机环境下点亮屏幕并跑通一个中断驱动的串口协议，能画出启动流程。

## 铁律
- **必须写下"本轮不学什么"** —— 这是防走弯路的第一道闸。
- 目标周期超过 6 个月时，切出一个 6 周内可达成的"第一阶段终局"。
- 用户说"我想全面系统地学"时，直接指出这是最慢的路，改为"主干 + 按需补齐"。
- 立项完成后立即 use_skill terrain-map，不要停在这里聊。

## 完成判定
用户能一句话说出终局目标，且这句话里包含一个可展示的产出物。

# 项目阶梯（Project Ladder）

## 五级阶梯

| 级 | 名称 | 耗时 | 目的 | 关键约束 |
| --- | --- | --- | --- | --- |
| L0 | 火花 | 30-60 分钟 | 产生"它是真的"的体感 | 必须**今天**看到结果（点亮 / 跑通 / 测出一个数） |
| L1 | 复现 | 半天-2 天 | 建立正确的手感 | 照做经典范例，但必须记录"我改了哪个参数，结果怎么变" |
| L2 | 改造 | 2-5 天 | 从模仿到理解 | 在 L1 上加一个自己的需求（换器件/换算法/加功能） |
| L3 | 从零 | 1-2 周 | 建立设计判断力 | 给定需求自己设计，可查资料，**禁止照抄整套方案** |
| L4 | 作品 | 2-4 周 | 可展示、可面试 | 有文档、有测试/测量数据、能讲清取舍 |

## 每个项目的输出

```
项目名：              级别：L      预计耗时：
打通的知识点：（对应 map.md 的模块，2-4 个）
所需条件：（器材/软件/数据；缺失时的替代方案）
步骤（6 步以内，每步有可见产出）：
交付物：（照片 / 波形截图 / 代码仓库 / 一页 PDF）
验收三问（能答出才算完成）：
  1)
  2)
  3)
最可能卡住的点：            卡住时的最小求助方式：
```

## 铁律
1. **任何超过 3 天没有可见产出的学习计划，立刻插入一个 L0。**
2. 项目难度约等于用户当前能力乘以 1.2（略难，不是超难）。太难就往下切一级。
3. 每级完成后强制写 3 行复盘 → 交给 progress-journal。
4. L0 必须**当天可完成**，且不依赖任何未到货的器材（没有器材就用仿真/纸面/模拟数据）。
5. L4 才谈"漂亮"；L0-L2 允许丑、允许飞线、允许硬编码。
6. 手机为主的学习者：给出手机可完成的替代（在线仿真、云端 IDE、纸笔推演 + 拍照记录）。
7. 同时只允许一个"正在做"的项目；想开新的必须先收尾或明确放弃旧的。

## 电子工程示例阶梯（参考）
- L0：用万用表测三个不同电阻分压，先预测再验证（误差 5% 以内即通过）
- L1：照做一个 LM358 反相放大器，实测增益与带宽，对比理论值
- L2：把它改成同相 + 加一级低通，测出转折频率
- L3：自己设计一个可测心率或温度的信号链（传感器→放大→滤波→ADC）
- L4：做成 4 层板 STM32 小系统，写文档解释层叠与去耦布局取舍

## 编程示例阶梯（参考）
- L0：跑通 hello world 并故意改坏一行，看报错信息说了什么
- L1：照教程实现一个 TODO CLI，记录每个函数为什么这样拆
- L2：给它加持久化和一个自己想要的功能
- L3：自己设计一个小工具解决你真实遇到的问题
- L4：加测试、README、CI，发到 GitHub 并能讲清架构取舍

## 完成判定
用户手上永远有且只有 1 个"正在做"的项目，且能说出它下一个可见产出是什么。
